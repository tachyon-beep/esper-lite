## The ONE genuine owner fork — the commitment premium (primes disagree)
The proposed freeze table contained an **internal contradiction** (gpt-prime): S5 set the flat premium to 0 while S8 kept `fossilize_base_bonus=0.5` — but a flat 0.5 one-shot at FOSSILIZE **is** a flat commitment premium. The two primes resolve it opposite ways, and the disagreement is load-bearing:

- **claude-prime — premium must be > 0 (+0.5–1.0).** Under the §2.6 neutral-annuity construction, arm B's *complete* commit ledger is **strictly negative**: annuity−forfeited-stream = 0 (by construction), flat premium = 0, `fossilize_cost` −0.01, `fossilized_maintenance_cost` −0.002×~71, frozen-α during window ≤ 0, PRUNE-option destroyed during window ≤ 0. Every remaining term is a cost → commitment is **dominated** → the op head learns to prefer NOT committing → but the floor forces 93–94% commits anyway → P1 flat ✓ / no-farm ✓ / P2-null ✓ / 94%-floored ✓ → **ACCEPT-SETTLE fires on a policy the settlement taught to avoid committing.** The verdict rule is **bit-identical to success**. The "GAE picks up the +1.5pp terminal via future return" defence requires a ~1% reward-mass terminal signal to propagate ~75 epochs through a 95%-shaping reward — the exact channel `hindsight_credit` was built for; it fired 0.005%.
- **gpt-prime — premium = 0, and drop the entire `0.5+0.1c` one-shot to zero.** Exp 1's B arm is not testing whether the policy *wants* to commit — the hard floor is still load-bearing, so it *can't* freely choose; Exp 1 tests whether the settlement **accounting** is farm-free and P1-non-regressing (a SETTLEMENT-PROTOCOL-SAFE verdict = infrastructure behind a flag, NOT a product ship). The premium would muddy that clean accounting test; the commitment-*preference* test is Exp 2's job (arm C, floor repaired).

### The synthesis I recommend (a constructed middle neither prime proposed exactly)
**Premium = 0 for Exp 1 (gpt's clean accounting test) + claude-prime's pre-floor raw-logit commit-preference diagnostic made a HARD, VERDICT-CHANGING gate + a pre-committed Exp-2 premium response.** Concretely:
- Log the **op-head raw (pre-floor) FOSSILIZE preference at eligible HOLDING**, arm A vs arm B (free — PDR-0070 already logs pre-floor logits).
- **Pre-registered gate (verdict-changing, not a footnote):** if arm B's pre-floor commit-preference is *materially below* arm A's, the settlement priced commitment as **dominated** → **NOT SETTLEMENT-PROTOCOL-SAFE-as-priced**, regardless of P1/G-FARM/P2. Required response before Exp 2: add a flat, schedule-locked (un-farmable) commitment premium (+0.5–1.0) and re-run.
- This keeps the Exp-1 accounting test clean (no thumb on the scale) **and** defuses claude-prime's fatal case (the only instrument that distinguishes "settlement worked" from "the floor is hiding a suppressed policy" now *changes the verdict*), **and** honours claude-prime's own concession that the premium is "the fallback if C under-commits" by deferring it to where it changes behaviour (Exp 2, floor repaired).

**The owner's discriminating question:** *do you trust the raw-logit preference gate to catch a dominated-commitment policy?* If yes → premium 0 + gate (cleaner test; the data decides the premium in Exp 2). If not confident → bake claude-prime's flat +0.5–1.0 hedge in now (belt-and-suspenders, at the cost of muddying the accounting-continuity test). Either way the `+0.1·c` spot term dies (both primes agree — it is the sell-at-spike channel).

## Converged amendments — ACCEPTED (folded into the pre-registration; NOT owner forks)
1. **P2 pseudoreplication fixed (gpt-prime; has teeth).** Treatment is assigned at the **training-run/seed** level, not per decision. The old E5 ("well-powered — per-decision N is thousands") was wrong. Corrected unit: one P2 slope estimate per run (restrict to eligible HOLDING with FOSSILIZE legal + valid quote + frozen mask/cardinality; stratify on num_valid, lifecycle age, occupancy, round, remaining horizon, current mask), compared pairwise across the n=5/n=10 **runs**. **Consequence (go/no-go, surfaced now):** there is NO obs-v4/K=4 pilot with the quote estimator → the between-run slope variance is **unknown** → n=10 **cannot** be pre-certified as an adequate claim tier. The design MUST use gpt's blinded post-screen variance reassessment (arm labels concealed, no treatment contrast inspected, **frozen max-n written before launch**, reassessment rule pre-registered). A parametric power curve is a freeze-time drl task; the experiment is NOT "fundable as scoped" until it exists.
2. **Two-quote settlement design (gpt-prime).** Separate the **decision quote** `q_decision = EWMA(c_{≤t−1})` (visible to policy, the P2 predictor, lagged) from the **settlement quote** `q_settle = EWMA(valid c collected AFTER the request, before the boundary; span 5; ≥5 measurements; not visible at request; locked at the schedule-determined boundary)`. The annuity rate is `q_settle`, NOT `q_decision`. Because the request is already irreversible, the policy cannot select the realised confirmation-window noise → removes the sell-at-spike max-operator more directly than locking a pre-request EWMA.
3. **Signed-value invariant (gpt-prime).** Settlement must apply the identical clipping/sign semantics as provisional `bounded_attribution` across positive, zero, AND negative contribution. "Negative quote → annuity 0" is valid ONLY if the provisional stream applies the identical zero-plus-penalty transform — a negative quote must not let FOSSILIZE escape a penalty HOLDING would keep incurring.
4. **Add G-LEDGER (gpt-prime).** Hard mechanism guardrail: for a constant synthetic contribution sequence, discounted return is invariant to requesting FOSSILIZE within numerical tolerance. Report PV(provisional credit before boundary), PV(annuity), net replacement error (mean/median/upper-tail), completion + invalid-request rates.
5. **Redefine G-FARM as three tests (gpt-prime).** (a) spot-residual timing: the residual `(c_t − q_decision)` term in a request model must not be materially positive; (b) audit-cycle phase: request prob must not spike at a position relative to the fixed boundary after controlling for `q_decision` + horizon; (c) settlement overpayment: upper-tail settlement replacement error below a pre-registered materiality from the sealed r9 replay. (Selection on persistent `q_decision` is *intended*; selection on transient residual noise or audit-cycle geometry is farming.)
6. **Redefine G-QUALPRUNE — decision-level, per-run + bootstrap the baseline CI (BOTH primes, complementary).** claude-prime: the +6.89/+6.58 vs +6.08/+5.86 cohort gap is ~2 seeds of a learned deterministic selection with **no CI** → bootstrap it before freezing the "shrink >50%" threshold; if the CI is wide, widen the guardrail or demote to descriptive. gpt-prime: replace the raw cohort-mean gate with a per-run `P(PRUNE | q_decision)` among age-legal same-mask HOLDING decisions — quality-preserving means PRUNE-sensitivity-to-quote stays non-positive, top-quote seeds not pruned more than bottom-quote, and C−B does not reverse it. Do both; keep the cohort gap as a descriptive reference.
7. **Define G-DESTROY-TOTAL before the run (gpt-prime).** "Harmful destruction" = PRUNE of a top-decision-quote-tercile seed, or PRUNE followed by a pre-defined adverse host-accuracy outcome. Total PRUNE frequency alone is not a harm metric.
8. **E2 critic — keep non-HRA held-constant, but make post-hoc calibration a PRE-REGISTERED output (both primes).** The E2 reason ("critic mis-fit is a symptom of the observation gap, fixed by obs-v4") is a **live hypothesis, not a finding** (claude-prime). Pre-register: on arm A (obs-v4, honest inputs), does V_main's commit-penalty still overstate the realised MC penalty by ~4–6×? If yes → PDR-0066 re-opens and the round-11 unification is over-read #14. The critic stays non-HRA and identical across arms (not a confound); the calibration is a scored read, not another factor.
9. **F1 wording — "endpoint-matched," not "behaviour-identical" (gpt-prime).** `q_i=f+(1−nf)p_i` matches the current min/max envelope but NOT the hard transform's interior distribution → C−B estimates an *endpoint-matched differentiable primitive*, not "gradient alone, behaviour unchanged" (no unbiased differentiable form can be output-identical to the hard projection while restoring its censored derivative). Log full pre/post op distributions, full **categorical** op KL (not just sampled-action KL), per-op prob changes, raw-logit + transformed score-function norms, near-floor rate `q_i ≤ f+ε`.
10. **S1 — version the environment protocol + emit `FOSSILIZE_REQUESTED` / `FOSSILIZE_SETTLED` events (gpt-prime).** Re-interpret FOSSILIZE behind the settlement flag (no schema bump) but make the two lifecycle instants observable.
11. **Late requests — mask, don't fall back to an underspecified "settle at terminal" (gpt-prime).** Mask the request when there is insufficient time for the full ≥5-measurement window + the minimum settlement horizon, unless terminal settlement has a separately frozen formula. Avoids a second pricing regime at the episode boundary.
12. **Verdict taxonomy restructure (gpt-prime; == claude-prime's "infrastructure behind a flag, not a product ship").** SETTLEMENT-PROTOCOL-SAFE (B: ledger-continuity ∧ anti-farm ∧ P1 non-inferiority ∧ safety — permits landing behind a flag, NOT product benefit) / COUPLED-MECHANISM (C: greater quote sensitivity than B ∧ guardrails) / SHIP-COUPLED (COUPLED-MECHANISM ∧ powered P1 superiority C−A) / INCONCLUSIVE (P1 improves but P2 doesn't fire, or P2 fires while P1 underpowered) / REJECT (hard guardrail fail ∨ powered P1 regression ∨ no P2 and no product improvement). Sequential test order: P2 mechanism gate → P1 superiority → guardrail interpretation. B−A is honestly the **whole settlement protocol** (irreversible request + confirmation delay + frozen controls + replacement annuity), not pure annuity accounting — stated, not hidden.
